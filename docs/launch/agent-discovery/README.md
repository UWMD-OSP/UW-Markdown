# Agent-discovery kit (staged for launch)

Launch criterion F: an agent that has never heard of UW Markdown can find it,
write a record, and check that record without installing anything. The core pieces
are **built and tested but not published**. Directory eligibility and packaging
remain launch prerequisites, not completed listings. Nothing below is listed or live,
and wiring it in is a launch-day step for the owner.

| Piece | Where it lives | State |
|---|---|---|
| MCP connector (`uwmd_validate`, `uwmd_verify`, `uwmd_explain_code`) | [`packages/uwmd-mcp`](../../../packages/uwmd-mcp/README.md), with `server.json` for the MCP registry | `"private": true`; not on npm or any registry |
| Skill: write a UWMD record | [`skills/write-uwmd-record`](../../../skills/write-uwmd-record/SKILL.md) | In the repo only; not listed in any skill directory |
| Zero-install validator page | `tools/web-editor/validator.html`, built by `npm --prefix tools/web-editor run build:validator` into `tools/web-editor/dist-validator/` | Not copied into the site build |
| `llms.txt` with the agent tools | [`llms.txt`](llms.txt) here | The live site still serves `docs/downloads/llms.txt` |
| Example gallery | [`examples-gallery.md`](examples-gallery.md), regenerated by `node docs/launch/agent-discovery/gen-gallery.mjs`; the validator page has the same examples in its picker | Not a site page yet |

## Launch-day wiring (owner)

Do these in one PR, after the 5.0.0 packages are published, so every link
resolves the moment the site deploys.

1. **Validator page.** Add `npm --prefix ../web-editor run build:validator` to
   the `build:cloudflare` script in `tools/docs-site/package.json` (the
   Cloudflare Workers build). Then, in
   `tools/docs-site/scripts/prepare-public.mjs`, copy
   `tools/web-editor/dist-validator` to `public/validate`, as it copies the
   editor to `public/editor`. The page is served at `/validate/` (its Vite
   `base`).
2. **Gallery.** Copy `examples-gallery.md` to `tools/docs-site/examples/index.md`
   (route `/examples/`) and add it to the site navigation.
3. **`llms.txt`.** Replace `docs/downloads/llms.txt` with the staged
   [`llms.txt`](llms.txt). The diff only adds the "Tools for agents" section and
   one rule. Add the same links to `llms-full.txt` and the
   [AI guide](../../../tools/docs-site/ai/index.md).
4. **Connector.** Follow the "Launch-day listing" steps in
   [`packages/uwmd-mcp/README.md`](../../../packages/uwmd-mcp/README.md): drop
   `private`, publish with the release, choose the registry namespace, publish
   `server.json`.
5. **Skill.** List `skills/write-uwmd-record` where you choose (for example the
   Anthropic skills directory). The skill links only to public URLs.
6. **Check.** Load `/llms.txt`, `/validate/` and `/examples/` on the deployed
   site, and run one record through the connector from a fresh MCP client.

## Why staged, not live

The site deploys from `main`, so anything wired into its build goes live on
merge. Keeping the pieces out of the build until launch lets each be reviewed,
and keeps the owner in charge of listing and publication.

## Listing preparation and aggregate measurement

[Listing metadata](listing-metadata.json) describes the existing local stdio tools and marks unavailable policy URLs explicitly. Follow the [launch checklist](LAUNCH-CHECKLIST.md) for MCP Registry, Claude desktop/plugin and ChatGPT desktop eligibility. No public HTTPS connector or directory availability is implied.

`node scripts/adoption-counts.mjs` reads only anonymous public aggregate endpoints and writes one JSON report. Its bounded response parser keeps unavailable/compact values unknown, not zero. It never requests issue authors, fork owners, user lists, tokens or private analytics. See the checklist for the exact proxy limits.
