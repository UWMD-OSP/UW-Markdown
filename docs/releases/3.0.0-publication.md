## Module package retirement

RFC 0080 §6 makes 0.2.0 the final version of both module packages and has the
owner deprecate both names after publication is verified (wiki 11,
"Retirement"). The owner ran both `npm deprecate` commands on 2026-10-11,
after the release run. The registry now shows the retirement message on every
version of each name, `0.0.0-stage`, 0.1.10 through 0.1.13 and 0.2.0:

- `@uwmd/module-hospitality`: "Retired: hospitality is a builtin asset class
  in @uwmd/core 3.0.0 and later (RFC 0080). Use @uwmd/core; no module install
  is needed."
- `@uwmd/module-data-center`: the same message for `data_center`.

`latest` stays 0.2.0 for both, and existing installs keep resolving; npm
prints the message on install. Both packages are still in `release.yml` and
`release-packages.mjs`. Removing them is left to a later release, never the
one that shipped their final version.

## Lake 0.2.9 bootstrap

npm requires a package to exist before its trusted publisher can be
configured. Lake had never been published, so on 2026-10-11, before tagging,
the owner created it by hand: a `0.0.0-stage` placeholder (17:00:53 UTC, 2
files), then lake **0.2.9** (17:01:49 UTC) from the `v2.21.0` tag. 0.2.9 pins
core 2.21.0, has no `gitHead` and carries no provenance attestation, as a hand
publish does not. Its 18 files and the archive itself are byte-identical to a
local `npm pack --ignore-scripts` of `packages/uwmd-lake` from a clean
`v2.21.0` checkout (`npm ci --ignore-scripts`, build). It is not part of the
3.0.0 release: lake 0.2.10, published by the release run with provenance, is
`latest`.
