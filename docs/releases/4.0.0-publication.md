## Published contents and delivered packages

A clean online `npm ci` and build ran on the exact tagged source, under local
Node 24.14.1. The published files were compared with local
`npm pack --ignore-scripts` artifacts:

- **File names and contents** match in every package: core **462**, CLI
  **3**, signing **24**, batch **5**, Excel **87**, report **15**, lake
  **18**, **614** files in total.
- **Core, signing and lake archives** match byte for byte.
- **CLI, batch, Excel and report archives** differ only in the bin executable
  permission bits: published `0755`, local Windows `0644`. 2.17.0 through
  3.0.0 showed the same difference.

The registry-installed CLI reports **4.0.0 / Protocol 4.0.0 / Format 3.0**,
and its implementation manifest claims the `verifier` tier with all six
profiles. The full RFC 0004 portable driver (`conformance:v2`) from the tagged
tree passes **336/336**, with no failures, skips or unverifiable results:
Reader 17, Verifier 281, the module profile 1 and starter products 37.

```text
python conformance/runner/runner.py --impl "node <isolated-consumer>/node_modules/@uwmd/cli/bin/uwmd.mjs" --no-skip --manifest-out <evidence>/published-cli-portable.json
```

The same isolated consumer loaded the registry-installed packages. All **19**
checks pass:

- `@uwmd/core` and `@uwmd/core/browser` report core 4.0.0, Protocol 4.0.0 and
  Format 3.0. `SUPPORTED_FORMAT_VERSIONS` is exactly `['3.0']` and
  `SUPPORTED_PROTOCOL_VERSIONS` exactly `['4.0.0']` in both entries.
- `REFERENCE_IMPLEMENTATION_MANIFEST` claims the `verifier` tier with all six
  profiles; `ASSET_CLASSES` has twelve, including `data_center` and

## Module packages and other registry versions

RFC 0081 D6 deleted `@uwmd/module-hospitality` and `@uwmd/module-data-center`
from the repository, so 4.0.0 does not publish them. The registry confirms
it: neither name has a version newer than its final 0.2.0 from 3.0.0, `latest`
stays 0.2.0, and every version of each still carries the 2026-10-11
retirement message (see the
[3.0.0 publication record](3.0.0-publication.md#module-package-retirement)).

The registry also shows three earlier versions now carry owner deprecation
messages that point at the current packages: lake `0.0.0-stage`, and the
stray 2026-08-16 `0.3.0` of Excel and report. The messages are recorded in
the evidence file. They change no published artifact, and none is part of
4.0.0.
