# UW Markdown 1.1+ machine-interchange release plan

**Status:** RFC 0014 accepted; implementation planning

**Release line:** post-v1.0.0

**Owner:** jaredmaxey

**Last updated:** 2026-07-26

## Outcome

Ship stable machine representations of the existing UW Markdown record without
changing the `.uw.md` authoring format or weakening its audit and byte-preserving
edit guarantees. The release line promotes the existing `.uw.json` sibling,
adds a secure XML codec and a normalized CSV bundle, and exposes the same
representations through library, CLI, HTTP-profile, and MCP-profile surfaces.

The design authority is [RFC 0014](../rfcs/0014-multi-format-interchange.md).
This document coordinates releases; it does not accept the RFC or create
normative behavior by itself.

## Version map

UW Markdown versions each surface independently. “1.1+” is a release train, not
a single version applied everywhere.

| Surface | Current | Planned | Reason |
|---|---:|---:|---|
| `.uw.md` format | 1.1 | **1.1 unchanged** | No Markdown syntax or section semantics change. |
| UW Protocol | 1.1.0 | **1.2.0 candidate** | Additive representation discovery and fidelity declarations. |
| `@uwmd/core` | 1.0.0 | **1.1.0 candidate** | New envelope/schema and codec registry; existing APIs remain compatible. |
| `uwmd` CLI | 1.0.0 | **1.1.0 candidate** | Adds explicit encode/decode/convert commands and named views. |
| UW Document Envelope | existing `.uw.json` 1.1 library shape | **1.2 candidate** | Canonical output removes duplicate `meta` / `prose`; readers retain legacy 1.1 compatibility. |
| UW JSON mapping | implicit | **1.0.0** | First independently specified encoding of the envelope. |
| UW XML mapping | none | **1.0.0** | First XML mapping. |
| UW CSV bundle | summary view only | **1.0.0** | First model-fidelity multi-file CSV mapping. |

The first public `v1.0.0` publication remains the immediate release prerequisite.
No 1.1+ package is published until `v1.0.0` exists and its install path is
verified.

## Governance gates

RFC 0014 changes implementer behavior and touches the protocol, public API,
schemas, and future conformance contract. It follows the normative path in
`GOVERNANCE.md`:

1. Open RFC 0014 as a draft PR.
2. The BDFL marks it `active` when the proposal is ready for public comment.
3. Record the activation date and keep the PR open for at least 14 calendar days.
4. Resolve design questions and record decisions in the RFC/PR.
5. Obtain explicit BDFL approval.
6. Merge the accepted RFC, including its target version map.
7. Land the reference implementation in linked, reviewable phases.
8. Update the normative specs, schemas, conformance corpus, `VERSIONS.md`, and
   `CHANGELOG.md` in lockstep with the phase that activates each contract.
9. Publish package versions only after all release gates pass.

### Bootstrap exception

On 2026-07-26, the BDFL waived the 14-day comment period and accepted RFC 0014
because the repository has one maintainer, no other contributors, and no
published consumer dependency on this proposal. The exception is recorded in the
RFC and PR history. It does not amend `GOVERNANCE.md` or remove the normal
comment period for future multi-contributor changes.

Acceptance authorizes the phased implementation below. Features MUST NOT be
described as implemented, conforming, or shipped until their specs, schemas,
reference code, and conformance fixtures land together.

## Architecture review findings

### Resolved in the draft

- **No Markdown version bump:** the proposal is encoding/protocol work, not a
  change to `.uw.md` syntax.
- **Transport scope:** HTTP and MCP are companion binding profiles. Protocol 1.2
  standardizes representation descriptors and fidelity; it does not require a
  network server for any conformance tier.
- **Source fidelity:** byte-preserving Markdown editing remains a distinct
  `UWSourceAdapter` contract. A codec that only receives an envelope cannot
  recreate the original Markdown bytes.
- **Views versus interchange:** existing renderer JSON and one-row CSV remain
  named, lossy views and cannot advertise model fidelity.
- **HTTP negotiation:** standard `Accept` wildcard rules govern negotiation;
  structured suffixes aid content-type dispatch, not suffix-wildcard matching.
- **Digest input:** volatile generator fields and the digest field itself are
  excluded from the semantic digest.
- **XML extension keys:** invalid or unknown XML names use an explicit
  `<uw:member name="…">` mapping instead of being converted into unsafe element
  names.

### Decisions recorded 2026-07-26

- The normalized bundle is the authoritative, model-fidelity CSV representation.
- Canonical envelope 1.2 emits only `content._meta` and per-block prose; legacy
  `.uw.json` 1.1 duplicates remain accepted on input and conflicts are rejected.
- The first reference exporter ships all six approved view profiles:
  `deal_summary`, `rent_roll`, `operating_statement`, `debt`, `valuation`,
  and `sources_uses`.

### Requires review before activation

- ZIP media type versus `application/zip` plus a profile parameter.
- Stable HTTPS resource identity versus a future `uwmd:` URI scheme for MCP.
- Default input, nesting, ZIP expansion, and file-count limits.
- Whether the neutral container field is permanently `envelope_version` or
  ultimately becomes `document_version`.

## Candidate CSV bundle

The recommended v1 bundle separates structural joins from arbitrary values and
keeps business-friendly exports optional:

| File | Cardinality | Required | Purpose |
|---|---:|---:|---|
| `manifest.json` | 1 | yes | Versions, digest, file inventory, hashes, view profiles, safety policy. |
| `document.csv` | 1 row | yes | Deal identity, envelope/format version, generator metadata. |
| `frontmatter.csv` | N rows | yes | JSON-Pointer path, JSON type, canonical JSON value. |
| `blocks.csv` | 1 row/block | yes | `block_ref`, collection, section, variant, ordinal, current/superseded state. |
| `block_values.csv` | N rows | yes | `block_ref`, scope (`annotation`, `meta`, `content`), JSON Pointer, type, canonical JSON value. |
| `prose.csv` | 1 row/prose region | yes | `prose_ref`, scope, section/block reference, exact Markdown text. |
| `views/*.csv` | varies | no | Named, explicitly lossy business/analytics tables. |

The normalized files are the model-fidelity contract. The first reference
release ships `deal_summary`, `rent_roll`, `operating_statement`, `debt`,
`valuation`, and `sources_uses` as optional view-fidelity files. They are
included when their source sections are present and are never round-trip inputs.

ZIP is the default interchange artifact; an unpacked directory is the debugging
and source-control form. Ordering, quoting, null handling, path grammar, and
formula-safety policy must be pinned by golden fixtures.

## Implementation phases

### Phase A — Envelope and JSON

- Publish `uw-document-envelope.schema.json`.
- Introduce envelope 1.2 with one authoritative `content._meta` and per-block
  prose location; retain legacy `.uw.json` 1.1 read compatibility.
- Add semantic canonicalization, digest, and equivalence helpers.
- Register `uw-json` and distinguish it from the `deal-summary` JSON view.
- Add golden and malformed JSON fixtures.

**Exit gate:** old `.uw.json` files read successfully; model round-trip and
semantic digest tests pass; no `.uw.md` behavior changes.

### Phase B — Registry and discovery

- Add representation descriptors to `ImplementationManifest` and its schema.
- Implement registry lookup and HTTP-compatible negotiation.
- Add `uwmd formats` and `uwmd convert` CLI surfaces.
- Publish informational HTTP and MCP binding profiles.

**Exit gate:** protocol 1.2 changes, schema, TypeScript mirror, documentation,
and fixtures agree; existing v1.1 implementations remain conforming.

### Phase C — XML

- Specify deterministic XML mapping and namespace.
- Implement a DTD/external-entity-disabled parser with resource limits.
- Add XML schema/tooling support and cross-format digest fixtures.

**Exit gate:** JSON ↔ XML semantic digests match across the golden corpus and all
hostile XML fixtures reject safely.

### Phase D — CSV bundle

- Finalize tables after review of the questions above.
- Implement directory and ZIP codecs with safe extraction.
- Add normalized round-trip fixtures and named view fixtures.

**Exit gate:** JSON ↔ CSV semantic digests match; spreadsheet opening cannot
execute untrusted formulas; ZIP safety cases pass.

### Phase E — API/MCP reference adapters

- Add example OpenAPI components and an MCP reference server package or example.
- Return compact JSON in structured tool results and complete/binary artifacts as
  resources or resource links.
- Reuse the same core registry, validator, and editor.

**Exit gate:** transport examples contain no independent serialization logic and
validate against the accepted envelope/schema contracts.

## Non-goals for the first 1.1+ delivery

- Changing `.uw.md` syntax or its Tier-2 byte-preserving edit behavior.
- Requiring HTTP or MCP support for existing conformance tiers.
- Standardizing every asset-class-specific wide CSV.
- Durable collaborative block IDs.
- Protobuf field-number governance, Arrow/Parquet model fidelity, or streaming
  event semantics.
