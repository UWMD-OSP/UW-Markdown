# 2.15.0 release candidate (unpublished)

Prepared on 2026-10-02 after the `v2.14.0` publication. It sits on released
`main` behind the Format 2.0 payload-unwrapping fix, which merges first as its
own change. The candidate carries RFC 0066, which Jared accepted on 2026-10-02
through three owner decisions:

- **D1.** The §VIII.2a section-context rule becomes normative for every
  section-rooted identifier. An identifier that cannot be resolved refuses
  with `CALC-RESOLVE-002`.
- **D2.** Lender-side metrics declare `senior`; `cash_on_cash` declares no role
  and refuses on a multi-tranche map.
- **D3.** The release target is core/CLI **2.15.0** with Protocol **2.19.0**.

Format stays **2.0**. No tag or publication is implied. The published
generation remains core/CLI 2.14.0, signing 0.2.18 and batch 0.8.13.

## Candidate version derivation

RFC 0066 changes what an ordinary calc identifier over a variant-map section
returns:
- **Previously:** a silent `null`.
- **Now:** one selected block, or `CALC-RESOLVE-002`.

It also adds `section_roles` to module calculation declarations. That is an
additive Protocol minor, **2.19.0**. Core/CLI take a minor bump to
**2.15.0**, per D3. Every dependent pins core exactly, so each manifest needs a
new version for the repin. Packages without a new API take a patch bump, as in
the 2.14.0 generation. No external dependency or workspace link changes.

| Package | Candidate | Published state |
|---|---:|---|
| `@uwmd/core`, `@uwmd/cli` | 2.15.0 | 2.14.0 |
| `@uwmd/signing` | 0.2.19 | 0.2.18 |

`CORE_VERSION`, core's optional `@uwmd/signing` peer pin, the root lockfile and
the exact local pins move with those manifests. The lockfile entries are edited
in place, 36 lines as in 2.14.0; a clean `npm ci --offline` and
`verify-lockfile` pass. Both receipt issuance baselines record engine 2.15.0
and protocol 2.19.0. The frozen `receipts/verify/03-result-disagrees` fixture
records engine 2.15.0, so its intended result disagreement stays testable. No
formula, quantum or source amount changed.

## Contract crosswalk

| Surface | Payload-unwrapping fix (merges first) | RFC 0066 calc variant resolution |
|---|---|---|
| Normative prose | None. Protocol §VIII.2 already maps an identifier to "the canonical block's `content`". | Protocol §VIII.2 adds the variant-map rule; also §VIII.2a, §VIII.2b `section_inputs`, §VIII.2c, §VIII.6 `CALC-RESOLVE-002`, §V.7 and §X `section_roles`. |
| Runtime | A single `blockPayload` accessor serves the evaluator, cascade, size registry, CC-13 and the Excel reader. | `resolveSectionBlock` drives the evaluator, cascade, refinement, `uwmd scope`, the web editor's Scope table and the Excel `SectionReader`. |
| Schema | None. | `section_roles` in the module-manifest schema, and the new `section-refinement-issue.schema.json`. |
| Packs | None. | 46 lender-side declarations declare `debt_structure: senior`; `cash_on_cash` declares none. Pack versions are unchanged. |
| Conformance | Unit tests only: flat versus envelope for the cascade, refinement and every Excel layout. | Eleven tier-3 fixtures, `variant-01` … `variant-11`; the portable runner grows from 78 to 89 cases. |
| Excel parity | Wrapped documents no longer write blank inputs. | Refused inputs and metrics write `#VALUE!` with a note. `EXCEL-EMIT-PATH` refuses a metric that would read a different block. |
| Absence and legacy | Flat (v1) documents read exactly as before. | A missing section is still `null`, and a standalone block reads as before. Period references keep §VIII.2a and `CALC-PERIOD-003`. |

## Release boundary

The candidate is not a tagged or published release. Merging it to `main`
publishes nothing. The `v2.15.0` tag requires owner authorization. Before
that tag is pushed:

- **Reconfirm the four npm trusted publishers** (core, CLI, signing, batch),
  as for 2.14.0.
- **Push the tag yourself.** The agent session can push branches but not
  tags, so the owner pushes the annotated tag on the merged release commit.

After the workflow publishes, verify the registry versions and provenance as
the [2.14.0 record](2.14.0-candidate.md) did. Then change RFC 0066 to
`implemented` and update the living release records.

Draft RFCs 0064, 0065 and 0067–0069 are outside this candidate. The RFC 0062
portable-runner cases (`claude/rfc-0062-portable-cases`) add tests only and
are not part of the 2.15.0 contract.
