# 2.14.0 release candidate (unpublished)

Prepared from canonical `main` at `c5df4c0` after a separate current-state
documentation reconciliation, then merged to `main` by PR #218 at `3a51cdf`.
PR #221 subsequently merged a shared decimal-quantization correction at
`356c2a1`; the source candidate now includes that correction, with no tag or
publication implied.
This candidate contains the already accepted and
integrated RFC 0062 same-day errata (`e49eb43`) and RFC 0063 final-period
boundary option (`413a645`). Protocol source is **2.18.0**, including the
2.17.1 errata; Format remains **2.0**. RFC status remains `accepted` until the
capability ships. The published `v2.13.0` tag still points to `7c250c2` and
the registry generation remains core/CLI 2.13.0, signing 0.2.17 and batch
0.8.12.

## Candidate version derivation

The optional RFC 0063 plan member is an additive public core and CLI
capability, so core/CLI take a minor bump from 2.13.0 to **2.14.0**. RFC 0062
is the separately accepted Protocol 2.17.1 normative erratum included in the
2.18.0 source contract. Every dependent has an exact local core pin, so its
manifest also needs a new version for the repin; packages without a new API
take a patch bump. No external dependency or workspace link changes.

## Contract crosswalk

| Surface | RFC 0062 same-day errata | RFC 0063 terminal boundary |
|---|---|---|
| Normative prose | Protocol §VIII.2a and Format §4.26 preserve separate same-day cash rows; a repeated requested date remains ambiguous. | Protocol §VIII.9.6 admits only the exact final monthly/quarterly exclusive boundary when explicitly selected. |
| Runtime | `period-validation.ts` omits cash-flow-only PS-02; `period-path.ts` refuses a repeated requested date and permits a unique one while whole-column lookup still refuses duplicates. | `protocol.ts` has the closed optional plan enum; `property-cash-flows.ts` checks its value and the final-period predicate. |
| Schema | No data-shape change was required for the same-day exception. | `property-cash-flow-plan.schema.json` has the optional closed enum without a default; the result plan references it. |
| Public API and CLI | Existing date selection and full-document validation expose the reconciled behavior. | `assemblePropertyCashFlows` and `assemble-property` read the optional plan member without a new command or flag. |
| Conformance | `cash-flow/valid-same-day-selection` checks separate rows and unique/ambiguous selection; the existing other-series and whole-column duplicate guards remain. | `property-cash-flow-assembly/boundary-*` checks absent, explicit legacy, opt-in, beyond-boundary and both cadences. |
| Absence and legacy | Unique-date ledgers and absent series retain their behavior; other registered series keep whole-series duplicate refusal. | Omission leaves the member absent from the copied result and preserves prior admission/refusal; explicit `within_final_period` keeps the legacy timing rule. |

## Release boundary

The candidate is integrated on `main` and awaits owner release review. It is
not a tagged or published release. The release step requires owner authorization
for the `v2.14.0` tag. The tag triggers `.github/workflows/release.yml`; confirm
the npm trusted publisher for each of core, CLI, signing and batch immediately
before it is pushed, and complete the pending legacy-package deprecation
handoff in [`HUMAN-npm-trusted-publishers.md`](../handoff/HUMAN-npm-trusted-publishers.md).
After the workflow publishes, verify registry versions and
provenance, then change RFCs 0062 and 0063 to `implemented` with the shipped
version and update living release records. Neither a tag nor publication is
authorized by candidate preparation.

RFC 0064 is a separate draft reserve-account investigation. It is excluded
from this release's normative contract and cannot be used to relax RFC 0045's
reserve refusal.
