# Authenticate-first receipt proposal — isolated, unaccepted

Owner direction2026-10-17 selects supplied-signature authentication **before
financial recomputation or a recomputation-refusal verdict**. This lab closes a
bounded procedure/counterexample proof. It does not activate production receipts,
change numerical graphs or accept RFC0088.

## Exact proposal boundary

The explicit ESM loader imports current receipts.js through a research-only
query. It relocates that actual function's supplied-signature AST stage immediately
before its actual compute try-block. It removes recomputed from the two early
authentication exits, because no calculation has run. It changes no subject,
reference, pack, result-comparison or digest operation and never writes source
or dist. Test-worker duplicate loader delegation is idempotent only for the exact
injected import marker; otherwise current topology and both auth exits must match.

Current wire assertion, record canonicalization, subject digest, held-input
mismatch and unavailable-input/pack/backend preflights stay earlier. Missing
backend remains RCP-08. A valid supplied signature is checked once before any
compute; an invalid signature or uncanonicalizable signature payload returns
RCP-01 without recomputed output. Backend throws retain transport behavior.
Unsigned receipts skip authentication and gain no signature claim. After the
stage, current compute refusal is RCP-03 with[], finite result coverage/value and
engine rules remain RCP-02/03/07, and result-digest corruption remains later RCP-04.
The complete ordered table is in draft RFC0088.

The synthetic receipt is **actually issued** through current public model APIs
for a finite one-calculation research pack. A deliberately changed supplied
pack declaration forces actual typed IRR refusal for a phase-control context;
this does not assert that a trusted published pack may change in place. Real
Ed25519 uses a deliberately public disposable test seed, with independently
canonicalized current receipt-to-signing-payload binding. No issuer trust or
financial accuracy is claimed.

## Remaining gates

This is a one-host, source-bound research proposal, not deployed verification,
accepted normative wording, conformance activation or independent cross-platform
proof. Final production placement, typed error and optional result transport,
joint normative receipt text/conformance and independent material-claim review
remain required. A separate root-owned public primitive implementation must
expose the same selected kernel without activating financial consumers early.
Raw-domain/resource, final consumer coverage and scoped platform/spreadsheet
proofs remain RFC0088 gates; B and stability rearrangements are not selected.
No prelaunch compatibility, migration, artifact-retention or version recommendation
work is required. RFC0088 staysdraft, with no activation, release or publication.
