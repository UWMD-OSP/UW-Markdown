# Composed numerical receipts and real signature precedence (unaccepted)

This bounded experiment closes one integration-evidence gap: actual receipt
issuance/recomputation for a complete pinned-kernel IRR graph, followed by real
Ed25519 verification and accepted refusal/engine/signature precedence. It uses
only public disposable test-key bytes. Cryptographic byte validity is not trust,
producer identity, financial completeness or approval of RFC0088.

The finite input and independent reported result are reused from the existing
frozen Python multi-period IRR trajectory. No 4204-word, 178-math or 4730-row
study is repeated. The old frozen endpoint receipt/source remains unchanged;
new research-signed clones test candidate recomputation refusal before a real
backend could run. They do not authenticate an original historical signature.

Every re-signed, tampered or metadata-edited receipt is a new synthetic artifact.
The experiment retains existing receipt fields and the existing engine name,
using explicitly synthetic experiment versions where a branch control needs
them. These are not package-version allocations, a protocol selector or a
historical compatibility layer. Existing production procedures and precedence
are not changed; only numerical operations in returned in-memory module source
are substituted by the previously reviewed isolated loader.

Commands (fresh own verifier build already available; no dependency install):

```sh
python -B experiments/numerical-0088/composed-receipts/capture.py --capture NEW_DIRECTORY
python -B experiments/numerical-0088/composed-receipts/capture.py --check experiments/numerical-0088/composed-receipts/evidence
node experiments/numerical-0088/composed-receipts/check.mjs
node experiments/numerical-0088/composed-receipts/check-binding.mjs
```

Capture refuses an existing destination, records exact current checkout/source/
dist/runtime/command identities, checks source and dist immutability, and freezes
full receipt objects, canonical signing payloads, backend calls and numerical
primitive events separately from the older evidence. Unmodified and baseline
loader controls run only two finite success controls; the candidate runs the
bounded matrix. No full workspace/corpus/native research loop is run.

The first capture is frozen in `evidence/manifest.json` at checkout
`f29258a2528f56b7536b40aae108e4a63a7aadc4` (tree
`b8a2bda34b67498d8c0b15767ebdf30cad43bccb`), after merging accepted main
`afcc615897aca301c7b5ec070bba7c0bd253e4ef`. It records Windows AMD64,
Python 3.12.3, Node 24.14.1, V8 13.6.233.17-node.44 and OpenSSL 3.5.5.
Thirteen compressed artifacts retain complete raw observations, signed payloads,
backend calls, loader transformations and primitive events. All source/dist
identities were equal before and after execution. Offline checks independently
verify 18 real Ed25519 signature byte-validity outcomes across 19 candidate
controls; they do not rerun receipt APIs.

Unmodified, baseline-loader and candidate issuance agree exactly for the frozen
multi-period IRR input, including the independent Python reported binary64 word
`3fb6c64e16bf6113` (`0.088963394693`). A valid signed receipt reaches the real
backend once and verifies even when verifier engine-version metadata differs.
Wrong reported-value controls deliberately edit the result; these are synthetic
finite disagreements, not an observed natural host/candidate numeric difference.
With a newly valid signature they preserve same-engine RCP-03 versus
other-version RCP-07/RCP-03; a retained invalid signature produces RCP-01 first.

The old endpoint receipt is reused as a frozen input, not reissued. Candidate
recomputation refuses: both newly valid and deliberately invalid research
signatures produce RCP-03 before any backend call. Missing-backend, subject,
held/unavailable input and unavailable-pack controls preserve their separate
accepted earlier exits. These observations do not change receipt precedence or
solve the refused computation. No new whole financial corpus, cross-platform
claim, accuracy guarantee, issuer trust or normative acceptance follows.

A separate post-capture `check-binding.mjs` leaves the original observer and
artifacts unchanged. It reconstructs the accepted signing projection
`canonicalize({...receipt, signature: null})` using the exact pinned accepted
canonicalizer source/dist; it does not call `receiptSigningPayload`. It requires
all 19 exact receipt/payload and source bindings, 18 recorded real-signature
outcomes and the endpoint clone's equality to its original except for the new
research signature. Three in-memory controls reject a detached recorded payload
after receipt-value, metadata or payload edits. This supplies an independent
binding check, not a new JCS implementation or financial oracle.
