# RFC0089 decision proof: minimum projection and authentication (unapproved)

This is a narrow owner-decision checkpoint, not another codec or production
contract. It reuses seven complete frozen candidate models and four exact source
files already preserved by the original labs. It does not modify their bytes,
the21/60 artifacts, the BOM corrective evidence, normative contracts, receipt
rules, public APIs or versions. All E_NEXT/C_NEXT labels remain illustrative.

## Recommended boundary and what executes

`projection.mjs` gives exact candidate extension/history minimum values using
tagged single/variants entries, null-first exact identities, duplicate refusal,
authored metadata and content without `_meta`/`_notes`. These are minimum
examples, not a full candidate validator or portable Reader. Full annotations,
Envelope block extras and prose remain in the complete Envelope; the portable
minimum is not the signed subject. Unrelated builtin/append-only projections
are not redesigned. The source guard's stronger requirements remain separate.

`auth-review.mjs` uses Node's actual Ed25519 implementation and an explicitly
public fixed research seed. This is not a secret credential or trusted issuer.
Real signatures and verification prove byte binding only. Document-shaped and
scratch-built receipt-shaped inputs use the existing canonical signing-input
patterns with unallocated candidate subject labels. The receipt-shaped inputs
were never issued as candidate financial receipts; their declared values/policy
are synthetic controls, not a financial computation/validation claim.

Seven preserved models produce42 mutation pairs and14 label-change pairs.
Changing payload, metadata, notes or retained prose changes the full subject and
breaks both signatures. `_notes` and prose changes can leave the parse minimum
unchanged: using that minimum as an authentication preimage would miss them.
Object key order and excluded Envelope `generated_at`/`generator` do not change
the semantic subject. Metadata timestamps inside blocks are still committed.
Label changes break original signatures even when the new digest is unchanged.

Actual current verifier APIs are imported by an explicit file URL from a fresh
build whose **all source bytes** match recorded main `b2ac5d8f`. Every current
runtime module compiled from that source is hashed. No workspace alias chooses
another checkout. The record includes helper/spec/schema identities and exact
complete artifacts, signing payloads, source bytes and public results.

The four source controls separate these facts:

| Preserved source | Current source guard / conservative candidate document gate |
|---|---|
| Singleton | Admitted; exact complete D1 projection equals frozen model; one gated research signing call. |
| One-peer variants | Admitted; exact complete D1 projection equals frozen model; one gated research signing call. |
| Mixed null/default peers | Existing INT15 source refusal; zero gated candidate signing calls. |
| Ordered extension history | Existing INT15 source refusal; zero gated candidate signing calls. |

The other three model-only examples have no attributable source, so the gated
candidate document path refuses. Their raw cryptographic controls may still
verify: any key can sign arbitrary bytes. That is not source admission.

For admitted sources, current-label document artifacts and actual current-regime
constant-pack receipts verify with real crypto backends. The pack computes only
literal1 as a synthetic control. Changing source `_notes` returns INT11/RCP01,
backend0, while retaining the original signatures. Duplicating an active source
selection refuses INT15. Candidate artifacts with valid bytes still return
actual INT14/RCP10 and backend0 in current verifiers. RCP10 here requires the
changed subject digest as well as differing canonicalization metadata; it is
not a blanket refusal of unknown receipt canonicalization-version strings. Relabelled current versions
return the existing source/subject refusal. This is observed current behavior,
not a future candidate state-machine implementation or backward-support path.

The separate `receipt-version.mjs` control retains accepted Receipt §5.5:
version-only canonicalization metadata changes with matching source digests
proceed normally. Four actual public-API controls use the two admitted frozen
current-regime receipts and real Ed25519: retaining the old signature after
changing only that metadata returns failed/RCP01 with backend1; a new disposable
research signature verifies with backend1. This does not implement the named
`C_UNSUPPORTED` canonicalizer or migrate a historical artifact. It demonstrates
why strict unsupported Envelope/codec and V.13 subject refusal cannot silently
become a new blanket receipt rule. `frozen/receipt-version.json` preserves every
artifact, payload, result and backend count, the original auth evidence hash,
and exact helper/contract identities. Every production source and compiled hash
from the original auth record is checked again. Its default replay is read-only:

```powershell
node experiments/envelope-0089/decision-proof/receipt-version.mjs --verify-root "C:\path\to\fresh-source-pinned-verifier" --check
```

The mixed-peer current receipt RCP10 observation does not prove Envelope1.0 has
a complete source projection; its known representation problem is Issue365.
No candidate financial receipt is issued. V.13 is not made a prerequisite for
ordinary receipt issuance: receipts must retain their own accepted canonical
subject, parse and pack-recomputation obligations. Ordinary model fidelity does
not expand V.13 repeated/superseded-extension signing admission. RFC0085 history
completeness/authority is still draft and is not inferred from stored history.

## Read-only replay and evidence

```powershell
node experiments/envelope-0089/decision-proof/check.mjs --verify-root "C:\path\to\fresh-source-pinned-verifier" --check
```

The explicit build must contain the exact recorded production source; no install
or build runs inside this harness. `--create` is first creation only and refuses
existing observations. Default replay strictly compares every material field;
Node/OpenSSL/host metadata is recorded separately rather than rewriting answers
for another runtime. The openly known key makes Ed25519 signatures reproducible.
No live conformance baseline is reissued or overwritten.

`frozen/observations.json` records the executed helper commit/tree and complete
source/compiled/spec/helper hashes, public test key, exact models' digests and
minimum projections, real signature bytes/payloads and source/API outcomes.
The initial harness stopped before executing controls on a nonexistent literal
schema filename; the committed corrected filename then passed the full matrix.
This is Windows Node24 evidence, not a cross-platform cryptographic or complete
Verifier claim. Codec-domain limitations remain as recorded in the existing lab.

The recommendation is one coherent choice of tagged/null identity plus minimum,
total lexical XML/full CSV carrier, and a new complete semantic subject with
unchanged authentication admission. Exact labels, full domain fixtures, normative
text/schema/projection synchronization and independent version/release decisions
still precede acceptance. No5.0 tag/publication is authorized by this experiment.
